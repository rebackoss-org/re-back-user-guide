    Install re-back¶

    re-back is a single executable. There is nothing else to install beside it — the files it needs on first start are built into the binary. Choose the method that matches where you want it to run:

    • Linux install script (systemd)
    • Native binary without the script
    • Docker Compose
    • Kubernetes

    All options need a Backblaze account and outbound HTTPS access. The web interface listens on port 8080 by default.

    Keep the web interface private. Settings and backup controls are not password-protected. Anyone who can reach the port can change what is backed up, start a backup, or start a restore. Use localhost, a private LAN, a firewall, or a VPN. Do not publish port 8080 on the internet.

    Option 1: Linux install script (recommended)¶

    The script installs a systemd service, keeps configuration separate from the large state directory, and starts re-back at boot.

    1. Get a binary¶

    re-back is distributed to invited users; there is no public download page. Use the re-back binary from the release you were given and put it at deploy/re-back.

    Building from source requires access to the private repository. With Go 1.27 or newer, from a source checkout you already have access to:

    (cd app && go build -trimpath -ldflags "-s -w" -o ../deploy/re-back .)

    2. Run the installer¶

    sudo bash deploy/install.sh install --bin "$PWD/deploy/re-back"

    The installer places:

    What Where
    Program /usr/local/bin/re-back
    systemd unit /etc/systemd/system/re-back.service
    Configuration /etc/re-back/config.json
    State (identity, index, run history) /var/lib/re-back
    Logs /var/log/re-back

    By default the service runs as root, because a backup agent that cannot read a protected home directory silently misses files. To run with less privilege:

    sudo bash deploy/install.sh install --bin "$PWD/deploy/re-back" --user re-back

    The re-back user must be able to read every source volume. A system user with no home directory will not be able to read another user's 0700 home folder unless you grant access deliberately. Check before choosing this option.

    3. Open the interface¶

    On the same machine:

    http://localhost:8080

    From another machine on your private network, use the server's address:

    http://SERVER-IP:8080

    If the page does not load, see Troubleshooting.

    4. Service commands¶

    sudo systemctl status re-back
sudo systemctl restart re-back
sudo journalctl -u re-back -f

    Upgrade¶

    Build or copy the new binary over deploy/re-back, then run the installer again. It replaces the program and unit but leaves configuration and state in place:

    sudo bash deploy/install.sh install --bin "$PWD/deploy/re-back"

    Remove¶

    sudo bash deploy/install.sh uninstall

    This removes the program and service but keeps all backup state, so a later install can pick up where it left off.

    sudo bash deploy/install.sh purge

    This also deletes configuration, identity, indexes, and restore history. The next install will need a new machine account. Do not use purge as a normal upgrade step.

    Option 2: Native binary¶

    Use this when you want to run the binary yourself, for example under your own service manager, in a one-off test, or inside a system you already manage.

    1. Build¶

    Building requires access to the private repository. With Go 1.27 or newer, from a source checkout you already have access to:

    (cd app && go build -trimpath -ldflags "-s -w" -o ../re-back .)

    If you received a prebuilt binary, use that and skip this step.

    2. Create its directories¶

    sudo install -d -m 0755 /etc/re-back /var/log/re-back
sudo install -d -m 0700 /var/lib/re-back

    3. Run it¶

    Run as root so it can read everything you select:

    sudo env \
  BBAPP_CONFIG_DIR=/etc/re-back \
  BBAPP_STATE_DIR=/var/lib/re-back \
  BBRE_API_LOG=/var/log/re-back/api-wire.log \
  BBAPP_ADDR=:8080 \
  ./re-back

    BBAPP_ADDR=:8080 listens on all interfaces. To restrict access to the local machine, use BBAPP_ADDR=127.0.0.1:8080.

    If you do not set BBAPP_CONFIG_DIR and BBAPP_STATE_DIR, both default to /config. That is useful in a container, but usually wrong for a host install.

    For a permanent service, use the unit file in deploy/re-back.service as a starting point, or use Option 1 and let the installer manage it.

    Environment variables¶

    Variable Default Purpose
    BBAPP_ADDR :8080 Web interface listen address
    BBAPP_CONFIG_DIR /config Directory containing config.json
    BBAPP_STATE_DIR value of BBAPP_CONFIG_DIR Identity, indexes, run history, and other mutable state
    BBRE_API_LOG unset Optional wire log for troubleshooting; may contain sensitive request data, so protect it

    For a normal host install, set config and state to separate directories. This keeps the large, changing state out of /etc.

    Option 3: Docker Compose¶

    The Compose file builds or pulls the image, publishes port 8080, and keeps configuration and state in named volumes.

    1. Edit the source mounts¶

    Open docker-compose.yml and add a read-only mount for each folder you want to protect:

        volumes:
      - re-back-config:/config
      - re-back-data:/data
      - /mnt/photos:/mnt/photos:ro
      - /mnt/documents:/mnt/documents:ro

    The paths on the right are inside the container. Use those container paths when you add volumes in the web interface.

    2. Start it¶

    docker compose up -d --build

    If you want to use the published image instead of building locally, comment out the build: line first.

    3. Open the interface¶

    http://localhost:8080

    To keep the port off other network interfaces, change the port mapping to:

        ports:
      - "127.0.0.1:8080:8080"

    4. Logs and storage¶

    docker compose logs -f

    re-back-config holds config.json. re-back-data holds the identity, index, and run history. Do not remove these volumes unless you intend to start over.

    The container runs as root by default so it can read mounted source trees. If you switch to a non-root user, make sure the UID can read every mount.

    Option 4: Kubernetes¶

    The manifest in deploy/k8s.yaml creates a single-replica Deployment, a Service, and a 50 GiB ReadWriteOnce volume for configuration and state.

    1. Review the manifest¶

    • Increase the PVC size if you have a very large file count.
    • Pin the image tag instead of using latest if you need reproducible upgrades.
    • Add a volume and volume mount for each source tree you want to back up.

    The template does not include any source mounts. Without one, re-back has nothing to back up.

    Example addition to the Deployment:

              volumeMounts:
            - name: data
              mountPath: /data
            - name: photos
              mountPath: /mnt/photos
              readOnly: true
      volumes:
        - name: data
          persistentVolumeClaim:
            claimName: re-back-data
        - name: photos
          persistentVolumeClaim:
            claimName: re-back-source-photos

    Create the source PVC, or use another volume type appropriate for your cluster. Then use /mnt/photos as the volume path in the web interface.

    2. Apply it¶

    kubectl apply -f deploy/k8s.yaml

    3. Reach the interface¶

    The manifest does not create an Ingress. Use a port-forward for the initial setup:

    kubectl port-forward deploy/re-back 8080:8080

    Then open http://localhost:8080. For permanent access, put it behind your normal private ingress or VPN. Do not expose it publicly without adding authentication.

    4. Important limits¶

    • Keep one replica. The state volume is ReadWriteOnce and the agent is designed as a single instance.
    • Do not delete the PVC to "restart" the pod. That deletes the machine identity and the file index.
    • The container needs enough CPU, memory, and temporary disk while hashing and uploading. The manifest's requests and limits are a baseline, not a guarantee.

    After installation¶

    Open the web interface. On first start re-back creates the files it needs under its state directory. You should see the Login screen with an empty Machine account card.
