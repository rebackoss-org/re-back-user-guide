    Restore files¶

    Restore is a separate operation from backup. You choose files from a machine's backup, choose where they should land, and start a download.

    Restoring does not change the backup in the cloud. It only reads from it.

    Restore needs a sign-in¶

    The Restore screen uses an authenticated Backblaze session. If you are not already signed in — for example after a restart — it asks for your account email and password, plus a 2FA code if the account uses 2FA. This is required even when restoring this machine's own backup, because the screen must list the machines on the account and fetch their file lists.

    • The sign-in is for this restore session. Your password is not saved by re-back.
    • If the service restarts or the session expires, sign in again.
    • Routine backups do not need this sign-in; they use the machine identity.

    Restore from this machine or another machine¶

    1. Open Restore.
    2. Sign in.
    3. Under Restore from machine, choose the source:
    4. this machine, or
    5. another machine on the same Backblaze account. If you create a new machine account while already signed in, click Refresh next to Load to re-fetch the list without reloading the page or signing in again.
    6. Click Load. re-back fetches that machine's file list.
    7. If the machine's backup is marked with a lock (🔒), provide its backup key as described below.
    8. Select files and folders.
    9. Choose the destination and options.
    10. Click Download selected.

    The file picker is a tree. Checking a folder selects everything under it. Select all and None are shortcuts; Re-scan refreshes the list from the server.

    Private-key backups¶

    If the source machine's backup was created with a backup key, the restore cannot read it without that key.

    • Use saved key uses a key already available to this installation. It only works if it is the same key that protects that machine's backup.
    • Enter own key lets you type the passphrase for this restore session. The typed key is not saved.
    • This screen can use a saved key, but it cannot change or remove the key. Key management is on Backup settings.

    If the key is wrong, the restore cannot decrypt the data. There is no override and no recovery reset. Use the passphrase you escrowed when the key was set.

    Choose where the files go¶

    There are two modes.

    Restore to another folder¶

    This is the safe default and the only mode allowed when restoring another machine's backup.

    1. Enter a Destination folder.
    2. Leave Restore in place unchecked.
    3. Click Download selected.

    re-back writes the files under the destination using their original folder structure, with the Windows drive letter removed. For example:

    C:\Users\alex\Photos\cat.jpg

    is restored as:

    DESTINATION/Users/alex/Photos/cat.jpg

    The destination must:

    • be writable by the user running re-back,
    • have enough free space for the selected files,
    • be a path visible inside the container or pod when using Docker or Kubernetes.

    If you restore into an existing folder, files at the same relative paths can be overwritten. Use a new or empty folder when you are unsure.

    Restore in place¶

    Restore in place puts each file back at its original local path.

    It is available only when the restore source is this machine's own backup. re-back refuses in-place restore from another machine because that machine's drive mappings would point at the wrong places on this host.

    In-place restore:

    • recreates missing parent folders,
    • opens each target file and prepares it for the expected size,
    • downloads the missing or damaged chunks,
    • can overwrite files at those paths.

    Treat it as a repair operation, not a merge. If you are testing a restore, use a temporary destination instead so you do not overwrite live data.

    Force full download¶

    Force full download (overwrite everything) is available for in-place restore. It skips the verify-and-skip pass and downloads every chunk again.

    Use it when:

    • the local disk is failing and existing reads cannot be trusted,
    • a previous in-place restore produced files that still look wrong.

    Without it, re-back verifies existing chunks and skips the ones that are already correct, which is faster and usually what you want.

    Parallel jobs¶

    Parallel jobs controls how many files are downloaded at once, from 1 to 20. The default is 4.

    Higher values can be faster until Backblaze starts answering with a busy or retry response. re-back backs off and retries automatically, but a very high number can make the restore slower. Raise it gradually.

    While it runs¶

    The Restore status card shows progress, file counts, bytes, speed, and any error.

    • You can leave the page; the restore continues in the background.
    • Reloading the page does not cancel the run.
    • Starting a second restore while one is running returns "a restore is already running".
    • If a run fails, Retry — resume in place appears. It retries the same selection and destination, skipping chunks that already verify.

    Do not start a second restore to the same destination while the first is still running.

    After the restore¶

    1. Open a few restored files, including one large file and one from a deep folder.
    2. Compare them with the originals or with a known-good copy.
    3. Only then rely on the backup.

    If files are missing from the picker, check the source machine and the backup date; the picker shows what the server has for that machine. If files restore but are unreadable, stop and check the backup key and the restore status before overwriting anything else.

    Restore quick reference¶

    Goal Mode
    Get a copy without touching live files Destination folder, Restore in place off
    Repair this machine's files at their original paths Restore in place on, this machine as source
    Recover from a failing local disk Restore in place + Force full download
    Recover files from an old or replaced machine Destination folder; in-place is not allowed
    Test that the backup is usable Destination folder, then open the restored files
