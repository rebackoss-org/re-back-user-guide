    re-back User Guide¶

    re-back is a backup agent for Linux that stores files in a Backblaze Computer Backup account. It speaks the same protocol as the Backblaze desktop client, so the Backblaze website sees the machine and its files as a normal computer backup — but the agent runs on your Linux machine, NAS, container host, or Kubernetes cluster.

    Independent project. re-back is not made by or affiliated with Backblaze. It is an independent implementation of the client protocol. Use it with an account and data you control, and test a restore before relying on it.

    This guide is for the person installing and running re-back. You do not need to know how the protocol works, but you should be comfortable with a terminal, editing a configuration page in a browser, and mounting the folders you want to protect.

    What re-back does¶

    • Connects a Linux machine to your Backblaze Computer Backup account.
    • Backs up one or more local folders, presenting each one to Backblaze as a Windows drive letter (C:, D:, and so on).
    • Runs a first full backup, then incremental backups. Files that have not changed are not uploaded again.
    • Can run continuously in the background, or only when you press Start.
    • Can restore files from this machine or from another machine on the same Backblaze account.
    • Optionally encrypts the backup with a private backup key that only you hold.

    The four screens¶

    The web interface has four sections:

    Screen What it is for
    Home Overall status, machine account creation, and machine renaming
    Backup Start, pause, resume, and stop a backup; view recent runs
    Backup settings Global defaults, include/exclude rules, backup key, and source volumes
    Restore Sign in, choose a source machine, select files, and restore them

    Before you install¶

    You will need:

    • A Backblaze account with Computer Backup available.
    • A Linux machine that can reach Backblaze over HTTPS.
    • Enough local disk for re-back's own state. This is much smaller than the backed-up data, but it grows with the number of files. A few gigabytes is usually plenty for a personal library; very large file counts need more.
    • Permission to read every file you want to back up. Running the service as root is the simplest way to avoid silently skipping protected files.
    • A decision about where the web interface can be reached. It has no login for the settings and backup controls, so keep it on localhost, a private network, or behind a VPN. Do not expose it directly to the internet.

    Recommended first run¶

    1. Install re-back.
    2. Open the web interface and create the machine account.
    3. Set a backup key if you want private encryption.
    4. Add at least one source volume.
    5. Run a backup and confirm it completes.
    6. Restore a test file to a temporary folder. Do this before you depend on the backup.

    Words used in this guide¶

    Term Meaning
    Machine account The entry for this installation in your Backblaze account. Backblaze calls these computers.
    Volume One local folder tree that re-back backs up. Each volume is shown to Backblaze as a drive letter.
    Drive letter The letter Backblaze uses in file paths, such as D:. It is a label, not a real Windows drive.
    Backup key An optional private encryption passphrase. When one is set, nobody — including Backblaze — can read the backup without it.
    State re-back's local records: identity, file index, run history, and restore history. Losing some of it can force a full re-upload.
    Restore in place Put files back at their original paths on this machine. Only allowed for this machine's own backup.

    A note on safety¶

    re-back is early software. Keep a second copy of anything irreplaceable until you have completed a restore test and are confident in the setup. The Restore screen is the source of truth for whether a backup is usable; a green backup status alone is not proof.
