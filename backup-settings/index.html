    Backup settings¶

    Open Backup settings from the left navigation, or the Settings button on the Backup screen.

    The page has two parts:

    • Global — settings that apply to every volume.
    • Volumes — one card per source folder, with its own path, drive letter, and optional filters.

    Changes are not live until you click Save configuration at the bottom of the page. Saving affects the next scan. A backup that is already running keeps the settings it started with.

    Global settings¶

    Transfer and schedule¶

    Setting Default What it does
    Upload threads 4 Number of files uploaded in parallel. Range 1–64. More threads can improve throughput but use more memory and bandwidth.
    Rescan every (minutes) 60 How often the background daemon looks for changes. A rescan is a stat-only walk and is normally cheap.
    Scan load threshold 0.7 Pauses scanning briefly when the system load is above this fraction of CPU capacity. A negative value disables load backoff.
    Change debounce (seconds) 5 Waits this long after a file change before rescanning, so a burst of writes becomes one scan.
    Paused Off Stops the daemon from starting automatic backups. A manual Start still runs. Useful during maintenance.
    Enable scan daemon Off Runs incremental backups forever on the rescan interval. This is the always-on mode. Manual backups work whether it is on or off.
    Watch local volumes for changes (fsnotify) Off Triggers an earlier rescan when a local file changes. It has no effect on NFS or SMB; the periodic rescan still catches those changes.

    Which mode should I use?

    • Manual: leave the daemon off and press Start on the Backup screen when you want a run. Good for a laptop or an occasional backup.
    • Always on: enable the daemon. It rescans on the interval and uploads changes without you pressing anything.
    • Maintenance: tick Paused to stop automatic runs without disabling the daemon.

    Filters¶

    Filters decide which files are eligible. They apply during the scan; they do not delete anything already backed up until a later scan records the file as gone.

    Pattern syntax¶

    All patterns are case-insensitive. There is no regular-expression mode.

    Pattern Meaning
    *.jpg Any file whose name ends in .jpg, at any depth
    Photos/* Everything below Photos at the volume root; * also crosses /
    *backup* Any path containing backup
    file?.txt file1.txt, fileA.txt, but not file10.txt
    node_modules Any path containing node_modules (plain text is a substring)
    */.cache/* Any .cache directory and its contents, at any depth

    Rules that are easy to get wrong:

    • A pattern without / is matched against the file name at any depth. So *.tmp works everywhere.
    • A pattern with / starts at the volume root. Photos/* does not match a folder called Old/Photos unless you write *Photos/* or a full path.
    • The full local source path also works, for example /mnt/media/Photos/*.
    • * matches any run of characters including /. ? matches exactly one character.
    • Plain text with no * or ? is a substring match, not an exact match.
    • Excludes always win over includes.

    Global include patterns¶

    One pattern per line.

    • Empty means every file is eligible.
    • If a volume has its own include list, that list replaces the global list for that volume. It does not add to it.

    Global exclude patterns¶

    One pattern per line.

    • These apply to every volume.
    • A volume's own exclude list is added to this list.
    • Use this for things you never want to upload: temporary files, caches, build output, and similar.

    Examples:

    node_modules
*.tmp
*/.cache/*
/var/lib/docker/*

    Apply native mandatory excludes¶

    This checkbox is on by default. It applies Backblaze's own mandatory exclusion list, which is the list the native desktop client always honors. It keeps re-back from uploading files Backblaze considers unsuitable, such as operating-system internals and temporary files.

    • The list is read from the state directory at bzdata/bzexcluderules_mandatory.xml.
    • It is re-read on every scan. If you replace that file with a newer copy from a Backblaze release, the new rules apply on the next scan without rebuilding re-back.
    • Turning it off lets you back up files that the native client would skip. This is usually a bad idea.
    • Turning it off does not remove files that are already in the index. They stay indexed and may be uploaded on the next backup.

    Client identity¶

    These fields control how re-back identifies itself to Backblaze. Most people should leave them alone.

    Field Meaning
    Running build The actual re-back program version. This is not the Backblaze version.
    Configured spoof The Backblaze client version re-back reports on the wire and in its User-Agent.
    Server advertises The latest Windows client version Backblaze publishes for this cluster.
    Client version Editable version string, such as 10.0.3.1075. It must look like a dotted version.

    Buttons:

    • Refresh advertised asks Backblaze for its current published version.
    • Adopt latest copies the advertised version into Client version.
    • Save configuration applies the change.

    Changing the reported version does not change the re-back build. If a backup starts failing after a Backblaze client update, refresh the advertised version, adopt it, save, and try again.

    Backup key¶

    The backup key is an optional private encryption passphrase for this machine's backup.

    • If you set one, the data is encrypted with a key derived from your passphrase. Backblaze cannot read it without the passphrase.
    • Store a copy somewhere safe before you continue. If you lose the passphrase, the backup cannot be restored. There is no recovery reset.
    • Set the key before the first backup if you plan to use one.
    • A generated 50-character key is available in the interface. Save it in a password manager or another safe place, not only in a browser tab.
    • If this machine's backup already has a key, the page shows Rotate instead of first-time setup. Rotation requires the current passphrase.
    • Remove key un-gates future backups. It does not decrypt or re-encrypt data that is already stored; older data remains protected by the old key. Keep the old passphrase if you may need to restore that data.

    If you are restoring a machine that has a private key, the Restore screen asks for the key. See Restore.

    Volumes¶

    Each volume is one local folder tree. Backblaze sees it as a Windows drive letter.

    First install: the built-in default is one volume at /backups on drive C:. That is a placeholder. Change the path to a real folder, or remove it and add your own, before the first backup. A volume whose path does not exist cannot be backed up.

    Adding a volume¶

    1. Click + Add volume.
    2. Enter the Source path — an absolute path on the machine or container, such as /mnt/photos.
    3. Choose a Drive letter that is not used by another volume.
    4. Optionally set include and exclude patterns for this volume.
    5. Optionally enable Require .bzre_mounted at this volume root.
    6. Click Save configuration.

    The volume's Volume ID is created when you save. Keep it. It is how the server recognizes the same volume across restarts.

    Volume fields¶

    Field Notes
    Source path The local directory to back up. It must exist when a backup starts. Missing paths are not silently invented.
    Drive letter The letter Backblaze sees, such as D:. Each volume needs a unique letter. Changing it changes how paths appear in the backup, so set it once.
    Include for this volume If non-empty, this list replaces the global include list for this volume. Empty means inherit the global list.
    Exclude for this volume Extra excludes added to the global list. Empty means only the global excludes apply.
    Require .bzre_mounted Skip this volume unless a file named .bzre_mounted exists at its root. Use it for NFS/SMB mounts.
    Volume ID Server-side identity, minted on first save. Do not remove and re-add a volume casually.

    Why the mount marker matters¶

    A network mount can disappear while the machine is still running. Without a guard, every file on that volume looks deleted, and the backup could record a mass deletion.

    If you enable Require .bzre_mounted:

    1. Create an empty file named .bzre_mounted at the root of the mounted filesystem.
    2. Enable the checkbox for that volume and save.
    3. re-back skips the volume whenever the marker is missing.

    When the mount comes back, the marker is visible again and the volume is processed normally.

    Changing a volume later¶

    • Changing the source path is allowed, but think of it as pointing the same server-side volume at a different local tree.
    • Changing the drive letter changes the paths Backblaze records. Avoid it after the first successful backup.
    • Removing a volume does not delete its backup immediately, but the server will eventually see the files as gone. If you want to keep them, leave the volume configured.
    • Adding a second volume with the same drive letter is rejected. Use a unique letter for each.

    Volumes inherited from another machine¶

    An inheritance brings the source machine's volumes across with their drive letters and volume IDs already set, and with an empty path: the last step of the wizard asks where each drive lives on this machine. Nothing is walked until you answer that. A drive you leave blank keeps its identity and its backed-up files but is not scanned here.

    Clearing backup state¶

    At the bottom of the page, under Dangerous, Clear backup state resets this machine's backup state. Type CLEAR BACKUP to confirm.

    It removes the identity, the ledger of what has been sent, the scan index, the account and host binding, the inherit record, and the encryption settings — including the passphrase and the key that wraps your file keys. The daemon stops.

    It keeps the volume list (paths, drive letters, volume IDs), the include/exclude rules, the schedule, the run history and the logs, so re-creating the machine does not mean re-typing them.

    It does not delete backed-up data from the account. Files already uploaded stay there; only this machine's record of them is gone. Encrypted files whose passphrase was discarded may no longer be readable.
